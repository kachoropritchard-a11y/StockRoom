# PROJECT_STATE

## Architecture
- **Monorepo** (npm workspaces): `server/` (API) and `web/` (PWA frontend). Environment: Node 24, Python 3.12, Git 2.56 (`C:\Program Files\Git\cmd\git.exe`, added to User PATH and initialised in `.git`).
- **Backend:** Node 24 running TypeScript natively (type-stripping, no build step), Fastify (`bodyLimit: 4MB`, logger secret redaction), Zod strict validation, helmet security headers, CORS allow-list, rate-limited authentication & uploads, CSRF header (`X-Requested-With: stockroom`) + Origin check.
- **Database:** SQLite via built-in `node:sqlite` (`PRAGMA foreign_keys = ON`, `PRAGMA busy_timeout = 5000`, `PRAGMA journal_mode = WAL`), plain `.sql` migrations in `server/migrations` (`001_init.sql` .. `009_system_initialization_and_pos.sql`), applied by `server/src/migrate.ts`.
- **Authoritative Stock Engine:** `server/src/inventory/engine.ts` is the sole writer to `stock_movements`. `stock_balances` is a SQL view (`SUM(base_delta_milli)` per organisation, product, and warehouse). Every write executes inside a `BEGIN IMMEDIATE` transaction (`tx()`), serializing concurrent writers and preventing overselling (`409 insufficient_stock`).
- **Auth, Governance & Security:**
  - **Password Hashing & Lockout:** `bcryptjs` (configurable cost, default 12) + constant-time `DUMMY_HASH` comparison on unknown emails + 5-attempt account lockout (`423 account_locked`).
  - **Sessions:** 256-bit `randomBytes(32)` tokens stored SHA-256 hashed in `sessions`, sent as `httpOnly`, `SameSite=Lax`, `Secure` (in prod) cookies or `Bearer` tokens. Password changes and account deactivations immediately revoke sessions.
  - **Separation of Duties & Thresholds:** Configurable `enforce_separation_of_duties` (`403 separation_of_duties_violation`) and `po_approval_threshold_cents` (`403 executive_approval_required`).
  - **Decision & Approval Recording:** Purchase orders, requisitions, and count sheets record `decided_by` / `approved_by` / `fulfilled_by`, `decision_reason`, and `decided_at` / `approved_at` / `fulfilled_at` timestamps, plus append-only `audit_logs` entries.
  - **Immutability Triggers:** `stock_documents`, `stock_movements`, and `audit_logs` are protected at the SQLite level by `BEFORE UPDATE` and `BEFORE DELETE` triggers (`stock_movements is append-only`, `audit_logs_are_immutable`).
  - **Safe File Uploads (`007_security_hardening.sql`, `/api/attachments`):** Strict MIME allow-list (`application/pdf`, `image/png`, `image/jpeg`, `text/csv`), magic-byte file signature verification (`%PDF`, PNG header, JPEG SOI, non-binary CSV check), path-traversal & dangerous-extension rejection, 2 MB limit, SHA-256 checksum storage, and download hardening (`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`).
  - **Error Sanitization:** Central error handler maps unexpected or 4xx/5xx errors to fixed machine-readable codes (`internal_error`, `bad_request`, `rate_limit_exceeded`, `payload_too_large`, `immutable_record`) and never exposes stack traces, SQL queries, or secrets to clients.
- **Frontend:** Vite, React, TypeScript, `react-router-dom`, Command-Center UI (`STOCKROOM OPERATIONS • LIVE`) with Light & Dark themes, Zimbabwe-inspired deep green (`#0b4f3a`), warm gold (`#c9962b`), teal (`#11a89d`), and indigo (`#4f52e8`) accents, WAI-ARIA `AccessibleTabs` with purpose banners and arrow-key navigation, `QuickTransferModal` (`Alt+T`), `ConfirmDialog` (`Esc` to close), live topbar **Notifications Drawer**, global keyboard shortcuts (`Alt+1..7`, `Alt+K` / `/`), PWA manifest + service worker + generated PNG icons.

## Unresolved Risks & Operational Notes
1. **Single-Node SQLite Concurrency Limit:** SQLite with `WAL` mode and `BEGIN IMMEDIATE` serializes writers safely on a single host, preventing overselling. If horizontal multi-node scaling is needed in the future, migrate the portable SQL schema to PostgreSQL (`SERIALIZABLE` / `SELECT ... FOR UPDATE`).
2. **Local Email Outbox for Password Resets:** Self-service password reset tokens are hashed in `password_reset_tokens` and written to the `email_outbox` table so the app runs self-contained without external credentials; in production, connect an external SMTP/transactional email worker to drain `email_outbox` and ensure `NODE_ENV=production` is set so `resetToken` is not returned in the HTTP response.
3. **In-Database Backup & Attachment Storage:** Point-in-time recovery snapshots (`system_backups`) and validated attachments (`document_attachments`) are stored inside SQLite with SHA-256 checksums. For disaster recovery against physical disk failure, operators should also schedule off-host encrypted copies of `./data/stockroom.db`.
